# 用户需求
当前的预览模式存在问题：
1. AI在不同的前端需求切换时，由于多个需求前端的占用port一致，都是3000. 会导致每次预览一个需求，其他需求的devServer会被关掉。
2. 当前的Web / PC / Mobile 预览的时候，web是3000、pc是3001，但是移动端又是3000. 开了web就不能开移动端。

# 我们的想法
1. 以nextharness.yaml为数据源，记录每一个需求，它对应的
    - 沙箱ID
    - 前端web端口
    - 移动端端口
    - PC端端口
    - Bifrost 规则
    - feature-name 尽量走中文
    yaml文件在需求开发的时候要注意维护。不可以出现新增需求后，没有改动这个文件的情况。

2. bifrost规则放弃当前的一个web的（coze-dev-online-local）、移动端的（coze-dev-prototype-mobile）、后端的（coze-claw-api-local）和（coze-bff-api-local）。
**全局只有一个规则**：规则采用bifrost的js script规则。通过Request Header来做规则切换。
x-tt-env-fe: <feature-name>-web web代理
x-tt-env-fe: <feature-name>-mobile 移动端代理
为什么没有pc，因为移动端和mobile要抢同一个域名，pc electron底层走了proxy server，不怕域名冲突。
然后还有一个脚本，用来快速切换 后端是否要代理的 ，为什么呢？因为后端通常一个需求改到了就要加这个规则，没改到后端就不用加 toggle_backend_proxy.sh，它的作用是注释或者取消注释当前的后端代理规则。
待验证：
```bash
./toggle_backend_proxy.sh
```
