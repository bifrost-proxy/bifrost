# 飞书进度卡折叠摘要、暗色主题与压缩包附件

## 背景

外部 Runner 的进度卡会随模型解释、工具事件和运行状态持续刷新。现状在运行期默认展开“执行过程”，长任务会占据大量会话空间；折叠后又缺少最新解释、当前工具、本轮成败计数和外部 Session ID。卡片折叠面板还固定使用 `grey` 背景，未完整遵循飞书 CardKit 的主题自适应样式。终态回复虽然会发送显式 Markdown 文件链接中的附件，但只识别少量单扩展名，常见的 `tar.gz`、`tgz`、`7z` 等打包产物不会自动发送。

## 用户目标验证清单

### 必须实现

- 运行中的“执行过程”默认折叠，用户仍可点击展开查看既有完整时间线和工具详情。
- 折叠栏上方常驻最新一次公开模型解释、当前正在执行的工具，以及当前轮成功、失败、执行中工具次数。
- 折叠栏标题展示总体执行步骤数和工具调用次数，两种口径不混用。
- Codex、Trae X、Claude Code 一旦通过运行事件提供外部 Session ID，立即显示在顶部状态栏；运行期尚未提供时显示“获取中”，终态仍未提供时显示“未提供”。
- 最终回复显式引用的常见压缩包/归档文件自动上传并作为飞书文件消息发送，包括复合扩展名。
- 出站文件在本地按飞书上传接口的 30 MiB 平台上限预检；超限、空文件、上传失败或文件消息发送失败时，跳过失败项并补发非阻塞提示，已经发布的任务结论保持成功。
- 进度卡的折叠面板只使用飞书主题自适应的默认背景/文本色；终态成功、失败标题继续使用官方语义模板色。

### 必须不破坏

- 展开后的模型解释、状态、子 Agent 和工具输入输出保持现有结构、裁剪预算与元素 ID 约束。
- 摘要只展示对用户公开的 assistant 内容，不推导或暴露隐藏思维链。
- 不扫描工作目录；只发送最终回复中显式 Markdown 链接指向的真实普通文件，并继续执行去重与大小限制。
- 图片、PDF、Office、Markdown 等既有附件识别和远程下载行为保持不变。
- 一个附件失败不能阻断其余附件，也不能把已成功的终态卡或服务状态改成失败；提示卡发送失败同样只记录日志。
- 卡片不写死十六进制、RGB、`black`、`white` 等颜色；Markdown 内容继续由飞书客户端按主题渲染。

### 必须真实验证

- 单元测试覆盖轮次边界、运行工具聚合、成功/失败/运行中计数、总体步骤/工具次数和 Session ID 三态。
- 单元测试递归检查生成卡片没有固定颜色，并断言折叠标题使用 `text_color: default`。
- 单元测试与 E2E 覆盖本地和远程 `tar.gz` 等归档链接解析，以及最终文件上传/发送。
- mock CardKit E2E 验证初始卡和后续更新均保持过程面板 `expanded=false`，摘要与即时 Session ID 出现在更新载荷中。
- mock 飞书 E2E 验证 30 MiB + 1 字节的文件不会调用上传接口、上传 API 返回非零错误时不会发送文件消息，两种失败都汇总为提示卡，且绿色成功终态卡已先发布。
- `human_tests/feishu-progress-card.md` 在飞书亮色、暗色主题下逐项检查折叠摘要、展开详情和成功/失败终态。

## 设计

### 当前轮摘要

“当前轮”从时间线中最后一个公开 `Thinking` 项开始；若没有公开解释，则以当前 turn 的完整时间线为范围。范围内的工具项按最终状态统计：`Some(true)` 为成功、`Some(false)` 为失败、`None` 为执行中。当前工具只列执行中的工具名，按首次出现顺序聚合同名工具，最多显示三个类型，超出部分显示“等 N 个”。

摘要使用独立且稳定、满足飞书 20 字符限制的 `agent_process_sum` Markdown 元素，位于 `agent_process_panel` 之前。最新解释取 snapshot 已公开的最后一次模型输出，并按卡片预算截断。摘要不改变 snapshot，也不改变展开面板中的完整时间线。

### 总体计数

总体步骤数为 snapshot 中去重后的可见时间线项数，包括公开解释、状态、子 Agent 和工具步骤；工具调用次数只统计工具时间线项。折叠栏标题统一为“执行过程：共 N 步 · 工具 M 次”，失败终态使用“失败前过程”前缀。

### Session ID

顶部状态栏直接读取现有 Runner summary/status 的 `external_thread_id`，其次读取 `external_conversation_id`。该状态随运行事件刷新，不等待 turn 结束。没有 ID 时，运行态显示“Session：获取中”，完成/失败态显示“Session：未提供”。展开状态详情继续保留完整且转义后的 Session ID。

### 主题自适应

折叠面板使用 CardKit JSON 2.0 的 `background_color: default`，折叠标题 `plain_text` 使用 `text_color: default`。正文 Markdown 不注入固定前景色或背景色。绿色成功和红色失败 header 属于飞书语义模板，继续保留。测试禁止生成卡片包含十六进制、RGB/RGBA、`black`、`white` 或固定黑白 font 标签。

### 压缩包附件

附件扩展名识别支持 `zip`、`tar`、`tar.gz/tgz`、`tar.bz2/tbz/tbz2`、`tar.xz/txz`、`tar.zst/tzst`、`gz`、`bz2`、`xz`、`zst`、`7z`、`rar`。复合扩展名必须优先于单后缀匹配，远程响应同时补充常见 archive MIME 映射。附件仍必须来自最终回复的显式 Markdown 链接，经过 canonical path 去重、普通文件检查和大小上限后才上传。

飞书官方 `POST /open-apis/im/v1/files` 明确限制文件不得超过 30 MB 且不能为空，超限错误码为 `234006`。因此用户期望的 250 MB 不能作为飞书单文件发送上限：Bifrost 的出站单文件上限收敛为 30 MiB，并在读取本地文件和下载远程附件时都做前置/流式累计检查，避免先把超大文件完整读入内存。250 MiB 仅保留为“引用消息入站文件”的单 Turn 总预算，不应用于出站上传。

终态卡先独立发布，再逐个上传/发送附件。附件失败记录 outbound file 日志并继续下一项；全部处理后把失败项汇总为“附件发送提示（不影响任务结论）”卡片。提示发送采用 best-effort，失败只记录日志，不向 Runner 完成状态或事件循环冒泡。

官方文档：<https://open.feishu.cn/document/server-docs/im-v1/file/create.md>。

## 风险与验证重点

- CardKit 全量实体更新时客户端如何保留用户手动展开状态由飞书实现决定；稳定 `element_id` 和一致的折叠组件结构是可用的状态关联依据。真实飞书用例需验证“手动展开后收到一次进度更新”的行为；若平台仍重置展开状态，再改为不替换外层面板的组件级更新。
- 摘要增加组件与文本预算；预算裁剪和 compact 卡必须使用同一摘要函数，避免降级后信息口径变化。
- 部分服务器返回通用 `application/octet-stream`；此时以 URL 文件名扩展名识别，不因 MIME 缺失丢弃显式归档链接。
